## 一、S5 的确切定义

你猜的 `score(d) = -min(rank_vec(d), rank_bm25(d))` —— **对**。我探针里的原文（`rag-review-scripts/_probe_recall_ab.py:102`）：

```python
def rank_vec(x):
    return np.argsort(np.argsort(-x))          # 0-based：0 = 最好

("S5_min_rank_fusion_n20",
 lambda v, b: (-np.minimum(rank_vec(v), rank_vec(b)).astype(float), 20))
```

即：**取两个名次里较小的那个、取负、按降序取 top-20**（再按 `_symbol_key` 去重）。
**不是** `1/(k+min(rank))`。不过两者对 `min_rank` 都是严格单调的，**排序结果等价**——你用倒数形式实现也一样。真正的差别在下面第 2 点。

### 复现前必须知道的 4 个细节

**1. 我的名次是 0-based**（`argsort(argsort(-x))` → 最优为 0）。
若你改 1-based，排序完全一致，不影响结果。但**只要还保留任何一种 `1/(k+rank)` 形式的 RRF，就必须统一基数**，否则 k=60 的含义对不上。

**2. ⚠️ 并列极多，而 `np.argsort` 不是稳定排序。**
`min(vec_rank, bm25_rank)` **不是单射**：`(vec=5, bm25=300)` 和 `(vec=300, bm25=5)` 都得 5，完全并列。523 个 chunk、top-20 边界上并列很密。`np.argsort` 默认是 introsort（不稳定），**哪些并列者进 top-20 靠的是排序运气**。
→ 建议把排序键做成元组 `(min_rank, max_rank, idx)`，或加一个微小次序项 `-min_rank - 1e-3 * max_rank`。
→ 为什么这条比听起来重要：**S5 宣称的优势是 R@1 +0.056，也就是 1 道题**。这个量级下"并列怎么破"足以构成噪声源，而且它会让消融表在不同 numpy 版本/排序实现下不可复现。

**3. overview 权重已经进名次了。**
我探针里 `vec_all = (idx.vecs @ qv) * w`、`bm_all = idx.bm25.scores(q) * w`，其中 `w = np.where(overview_mask, OVERVIEW_WEIGHT, 1.0)`。
所以 `rank_vec(v)` / `rank_vec(b)` 是**加权后**分数的名次，不是原始分数。**保持这样**——S1 也是这么算的，否则 S1 与 S5 不是在同一条件下比较。

**4. 「自适应，坏信号拉不动好信号」这个描述要改——你的数据不支持它。**
`-min(r_v, r_b)` 的语义是「**只要有一边排得好就加分**」，这是 **OR 融合**（按最优名次取并集），跟 RRF 的"两边都要还行"（AND 倾向）相反。
OR 融合**恰恰不抗坏信号**：BM25 若是噪声，总会有随机文档撞上 bm25 rank 1~5 被抬进 top-20。
实测对得上：抽象档里 **S5 R@10 = 0.500，纯向量 = 0.556** —— **噪声确实把 S5 拉到纯向量之下**了。S5 看着好，只是因为它赢了**现行的 RRF**（0.444）。

> 所以 S5 的正确定位是「**偏向单边强的融合**」，不是「自适应」。写进报告前先把这句改掉，否则你会给出一个自己数据不支持的机制解释。

## 二、那配哪套配置？（我建议改一下你的选择）

你说「就用 S5 当默认」。我建议**两档 delta 的主口径用 S1（现行 RRF）**，理由三条：

1. **S1 是项目今天真实在跑的东西。** 档① 用它跑出来的数就是「当前系统的能力」，是一个你能直接对外引用的数。换成 S5 之后，档① 的数字 = 题面效应 **+** 融合变更效应，两个变量一起动。
2. **P0-1（BM25 是噪声）是在档② 上测出来的。** 检验它的正确方式就是**在档① 上跑 S1**，看 S1 是否还输给纯向量——而不是预先换成 S5 把它绕过去。你上一条消息自己说了这是因果倒置，S5 当默认正是同一个错误的另一面。
3. **你同时说了「现在不定稿配置」。** 那就别把未定稿的配置塞进主指标。

### 顺带把融合消融变成 P0-1 的检验仪器

跑 **2 档 × 6 策略 = 12 格**（全本地，除合成缓存外不烧 API）。然后：

> **档① 上 S1 vs S2（纯向量）的差距，就是「BM25 在自然语域有没有信号」的直接读数。**

- 若档① 上 S1 ≈ 或 > S2 → BM25 恢复信号，RRF 在自然语域没问题，P0-1 降级为"档② 的配置问题"
- 若档① 上 S2 仍明显赢 → BM25 在**两个语域**都是噪声，那是**索引/分词层的问题**（不是融合方式的问题），方向完全不同

这样融合消融不再是一张孤立的表，它变成 P0-1 的判决工具。**6 种融合仍按"消融 + 标注 under-powered"报，不选优。**

## 三、配对 delta 报什么

### 先把三个量定义死（写进报告抬头）

| 量 | 定义 |
|---|---|
| `hit_it^k` | 第 i 题第 t 档（nat / abs）的 gold 是否进 top-k，∈{0,1} |
| `rank_it` | gold 在**重排后列表**中的名次，∈{1..20}；**未进召回 → 记为 21（= 召回深度 20 + 1）** |
| `rr_it` | `1 / rank_it`，未命中 → 0 |

**`21` 这个截断常数必须在报告里显式声明**，不声明 ΔMRR 就无法解释。

### L1 · 正式结论：每题每个 k 一张 2×2 配对表 + 检验

| | 抽象档命中 | 抽象档不中 |
|---|---|---|
| **自然档命中** | concordant | **b** = 口径救回 |
| **自然档不中** | **c** = 口径丢掉 | both miss |

报：`b`、`c`、`Δ = (b − c) / 18`、**bootstrap CI**（对 18 题重采样）、**McNemar 精确检验 p**（对 `(b, b+c)` 做二项检验，b+c 小的时候别用卡方）。

**为什么必须给 b 和 c，不能只给 Δ**：Δ = +0.11 可能是 `(2, 0)`（干净的方向性证据），也可能是 `(12, 10)`（口径效应和题目异质性搅在一起）——**同一个 Δ，两种完全不同的结论**。上个回合的功效分析就是被这个坑过的。

**所以报告里要写「不一致对数 b+c = X」，而不是「n = 18」。** 这个检验的功效**完全由 b+c 决定**，跟 18 无关。

### L2 · 补充：位置效应

- **ΔMRR**：配对检验（bootstrap CI + Wilcoxon 符号秩）。
  它捕捉 R@k 看不见的移动——`rank 15 → 12` 在 R@10 上毫无变化，但 MRR 会动。
- **`rank_nat − rank_abs` 的中位数与分布**，**只在「至少一档命中」的子集上给**。
  原因：两档都 miss 时差值恒为 0，这些题会把均值往 0 压，可它们代表的是"两档都无望"，不是"无口径效应"。
- 两条都挂上「截断常数 = 21」的声明。

### 不报

- 两个独立集合的均值差（已否）。
- **per-question rank 差不能当主指标**——它被截断值主导。

### 三条口径声明（不写就会被人误读）

**① 这个 Δ 不是纯「术语依赖度」，名字要改。**
档① 与档② 的差至少混了两个成分：**(i) 有 / 无领域术语**、**(ii) 沿 desc 反写 / 自然提问**。它测的是**合并效应**。
→ 命名成「**题面口径效应（术语 + 措辞风格）**」。要分解就加第三条臂（n=18 下不建议）。
→ **别叫「术语依赖度」**——那是给一个还没分解的复合量下单一命名。

**② 三个 k 以上的检验会抬高一类错误 → 指定一个主指标。**
有 R@1/3/5/10 四个 k，各做一次检验就是 4 次比较。
→ **预指定 R@10 为主**（基线 0.44 高于 R@1 的 0.06~0.22，可动空间大、不一致对多、功效最高），其余 k 只作描述性。
→ 别跑完以后挑一个显著的报。

**③ 档① 必须冻结后一次跑完。**
写完 18 条 → 冻结 → 跑一次。看到结果再回去改题面就是 tune-on-test。
**理由很实际**：档② 已经冻结（改不动了），而档① 是你新写的——**它是唯一会被无意识调优的那一档**。要迭代就留 6 道 hold-out 不参与改词。

### 而且那 8 道**不该直接当档①**

三条：

1. **它们是「贴 docstring 写的」**——你自己也说了"可能比真实用户的问法更贴字面"。这是**第三种语域**，既不是"去同源抽象"，也不是"真实用户提问"。直接拿来当档①，就是拿另一个极端档冒充能力分，只是这次偏在容易的一侧。
2. **你说了"按真实工程师怎么问再校一遍措辞，不照抄"**——那实质就是**重写**。重写之后，它跟"原始档"的关系只剩参考价值。所以别把"原料已在手里"当成省下 10 道题的理由。
3. **18 道必须同语域。** 若前 8 道来自"原始档（贴 desc）"、后 10 道新写，配对 delta 里会混进「两批题写作风格不同」的效应——**这正是上一轮「去同源去过头」的同类错误，只是方向相反**。

### 所以步骤 ③ 的准确形态

```
从探针取回 8 道原始题面  →  当「种子」用（保证 desc 覆盖）
新写 10 道                →  从「问题意图 + 你自己的 vLLM 知识」写
18 道一起过同一套纪律     →  ① 无 gold 符号名字面 ② 题间不撞车 ③ 报 desc 重合度
                          →  同一位作者、同一轮写完（避免风格分批）
冻结 → 一次跑完 → 算 delta
```

### 补一条：desc 重合度是审计工具，不是脚注

把档① 的 `query ↔ 目标 chunk 那句 desc` 重合度**对着档② 的 3.8% 公开报出来**。它同时告诉你"档① 到底落在哪个语域"：

- 若档① 量出来 ≈ 0.3+ → 你写出来的其实是"贴 docstring 的题面"（就是原始 18 题那个语域），**不是**真实用户提问 → "能力分"这个标签要再打折
- 若档① ≈ 0.05~0.15 → 语域确实不同于档②，Δ 才有"口径净效应"的含义

**这个数把一次主观出题变成可审计的量。** 不报它，谁也说不清档① 是什么。
